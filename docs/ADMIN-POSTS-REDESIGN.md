# 后台文章页重构审计与设计蓝图

## 0. 结论

- 重构对象：`GET /admin/posts.html` 文章管理页，以及它依赖的列表查询、归档动作和后台静态资源。
- 不在本次重写编辑器主体；编辑器已有独立的写作、自动保存、发布门禁和版本历史流程。
- 不新增数据库字段，不要求迁移；全部信息可从 `posts`、`post_drafts`、`post_tags`、`comments` 派生。
- 保留顶栏作为唯一页面标题，内容区不出现重复大标题。
- 推荐范围：第一优先（P0）完成筛选、分页、响应式、批量归档/恢复和行操作菜单；第二优先（P1）补齐未发布改动提示、留言回声、待审留言入口和可访问性；P2 才考虑保存视图、复制文章、定时发布。
- 归档继续作为唯一“移出公开站”的方式，不增加物理删除；归档可恢复为草稿，恢复后不会自动重新发布。

## 2. 现状问题

### 2.1 功能缺口

| 维度 | 现状 | 影响 |
| --- | --- | --- |
| 查找 | 只有一张按更新时间倒序的表，没有搜索、状态筛选、标签筛选 | 文章变多后只能滚动查找 |
| 数据量 | `PostAdminRepository::all()` 固定最多 100 条，没有分页 | 第 101 篇起在后台不可见，也没有提示 |
| 排序 | 固定 `updated_at DESC` | 无法按发布时间或标题查看 |
| 批量 | 没有多选，没有批量动作 | 归档多篇只能逐行提交 |
| 恢复 | 只有归档；没有明确的“恢复为草稿” | 归档后只能进入编辑器改状态，路径不直观 |
| 状态识别 | 只显示文章发布状态 | 已发布文章存在自动保存工作稿时，列表仍只显示“已发布”，容易误判线上内容 |
| 标签 | 列表完全不显示标签 | 无法在列表层判断归类是否缺失 |
| 读者回声 | 只有赞/踩，没有留言数 | 无法从文章列表发现待审留言 |
| 行操作 | 编辑、预览、查看、归档四个文字链接平铺 | 视觉噪音大，手机上还会被挤出视口 |
| 空状态 | 只有“还没有文章” | 筛选无结果时没有专门的恢复路径 |

### 2.2 布局与响应式

桌面结构是“说明 + 写新文章按钮 + 五列表格”，可用但信息密度低：没有总览，没有筛选，行操作占宽。

手机上问题更明显：

- `.admin-table` 在 `max-width: 760px` 下被强制 `min-width: 620px`。
- 390px 视口里，内容容器约 366px，表格实际 620px，靠横向滚动才能看到“更新时间”和“操作”。
- 截图里右侧被裁断，行操作在首屏不可见；没有滚动提示。
- 移动端没有专门的卡片视图、排序控件或批量操作区。

这不是“表格窄一点”的问题，而是移动端需要另一种信息布局。

### 2.3 数据与性能

- 列表只查 `posts`，再补一次 reactions 汇总；没有标签、留言、工作稿信息。
- 没有分页，靠 `LIMIT 100` 截断。
- 如果直接在模板里逐行查标签或留言，会退化成 N+1；本次必须批量取。
- 当前文章数量少，但结构上已经埋下“文章一多就找不到、看不到”的问题。

### 2.4 交互与反馈

- 归档使用浏览器原生 `confirm()`；与后台纸面视觉不一致，也无法承载更完整的后果说明。
- 操作成功统一显示“已完成”，没有区分“已归档”“已恢复”“批量归档 3 篇”。
- 筛选、分页、批量都没有，页面也没有结果数量提示。
- 没有“清空筛选”的出口。
- 行操作没有菜单层级，危险动作和普通查看混在一起。

### 2.5 可访问性

- 表头没有 `scope="col"`，表格没有 caption。
- 行内复选框不存在，因此也没有全选、选中数量播报。
- 操作链接没有明确的上下文，屏幕阅读器连续读“编辑、预览、查看、归档”时不知道对应哪篇。
- 手机触控目标偏小，且关键动作在横向滚动区外。

## 3. 外部参考与取舍

### 3.1 参考

- Ghost 的文章管理：状态/作者/标签筛选、批量选择、右键行菜单、保存视图。  
  https://ghost.org/help/organizing-content/
- Ant Design 列表页规范：筛选项放顶部，列表承担浏览、比较、批量处理和进入详情；批量操作可以放在页面底部。  
  https://5x-ant-design.antgroup.com/docs/spec/research-list
- Wingo UI 响应式表格：768px 以下把行改成卡片，标题、状态、2–4 个关键字段和操作菜单进入卡片；排序、筛选、选择需要独立控件。  
  https://wingo-ui.com/blog/responsive-table-mobile-cards
- UX Patterns 数据表格：移动端必须提供卡片、键值对或冻结首列等替代，不应把桌面表格硬塞进手机；默认每页 25–50 行。  
  https://uxpatterns.dev/patterns/data-display/table

### 3.2 吸收与不吸收

吸收：

- 顶部单列筛选区，不为了筛选再开侧栏。
- 状态计数直接做成可点击的状态轨，不再额外堆四张统计卡。
- 批量操作固定在底部，选中后才出现。
- 行操作收进菜单，编辑保留为唯一显式主操作。
- 手机上完全切换成卡片，不做 620px 表格横向滚动。
- 列表同时表达“线上状态”和“未发布工作稿”两件事。

不吸收：

- 不做 Ghost 的保存视图，首版文章量不值得增加一层状态。
- 不做 Ant 式通用企业后台换皮，保留奶油纸面、荧光笔、胶带和手账台账语言。
- 不做列自定义、列拖拽、内联改标题；对单人博客是过度设计。
- 不做无限滚动；后台需要稳定的页码和位置。

## 4. 设计目标

1. 一屏回答四个问题：共有多少篇、各状态多少、哪些有未发布改动、哪些有读者回声。
2. 找文章从“滚动”变成“状态 + 关键词 + 标签 + 排序”。
3. 高频动作不超过两次点击：继续编辑、预览、查看、归档/恢复。
4. 手机首屏就能看到标题、状态、更新时间和操作，不横向滚动。
5. 批量动作安全、可撤销语义清晰：归档是收进抽屉，恢复是回到草稿。
6. 视觉上仍是一本摊开的编辑台账，而不是通用数据后台。

### 5.3 页面层级

1. 顶栏标题：唯一页面主标题。
2. 状态轨：四种主状态的数量和入口；右侧“待审留言”快捷入口。
3. 工具栏：搜索、标签、排序、结果数、清空。
4. 内容区：桌面台账表格；手机卡片列表。
5. 分页：页码和总数。
6. 批量浮条：仅在选中时出现，桌面底部居中，手机底部通栏。

页面不增加第二层大标题、说明卡或统计卡。

## 6. 功能规范

### 6.1 P0：列表与筛选

- 状态：`status=all|published|draft|archived`，默认 `all`。
- 搜索：`q`，匹配标题和 slug，去首尾空格，最长 80 字符。
- 标签：`tag`，按标签 slug 精确筛选。
- 排序：`sort=updated|published|title`，默认 `updated`。
- 分页：`page`，每页 10 篇；超出页数夹到最后一页。
- 结果数：显示“筛选后 N 篇”；总篇数来自状态轨。
- 清空：回到 `/admin/posts.html`，不保留任何筛选。
- 所有筛选参数在状态切换、标签切换、排序切换和分页链接中保留。

### 6.2 P0：列表字段

桌面表格列：

| 列 | 内容 |
| --- | --- |
| 选择 | 当前页全选和行复选框 |
| 文章 | 标题（链接到编辑）、slug、未发布改动提示 |
| 状态 | 已发布/草稿/已归档徽章；发布时间或未发布说明 |
| 标签 | 最多两个标签，超出显示 `+N` |
| 回声 | 已通过留言数、待审留言数、赞/踩 |
| 更新 | `MM-DD HH:MM`，`title` 放完整时间 |
| 操作 | 编辑按钮 + 更多菜单 |

手机卡片字段：

- 复选框、标题、状态。
- slug、更新时间。
- 标签，最多两个 + N。
- 未发布改动提示。
- 留言、赞、踩。
- 编辑按钮和更多菜单。

### 6.3 P0：行操作

- 编辑：显式主按钮/链接。
- 预览草稿：新窗口，现有 `/admin/posts/{id}/preview.html`。
- 查看公开页：仅已发布，新窗口。
- 版本历史：现有 `/admin/posts/{id}/revisions.html`。
- 归档：非归档文章可用，弹出纸面确认。
- 恢复为草稿：归档文章可用，不需要二次确认。

不增加：

- 复制文章。
- 物理删除。
- 列表内直接发布。
- 列表内改标题。

### 6.4 P0：批量操作

- 选中当前页文章；支持全选当前页、取消选择。
- 底部浮条显示“已选 N 篇”和可用动作。
- 批量归档：只处理非归档文章，确认后一次提交。
- 批量恢复：只处理归档文章，恢复为草稿，不自动发布。
- 混合选择时同时显示两个动作，并标出各自可处理数量。
- 单次最多 100 个 id；服务端去重、只接受正整数。
- 成功后回到原筛选状态，并显示“已归档 N 篇”或“已恢复 N 篇”。
- 审计记录 `post.bulk_archived` / `post.bulk_restored`，载荷包含数量与 id 列表。

### 6.5 P1：状态与回声

- 已发布文章存在 `post_drafts` 时，显示“草稿待发布”小标记；筛选参数 `changes=1` 可只看有未发布改动的文章。
- 状态轨不把“有改动”混进“草稿”数量，避免概念混淆。
- 留言按文章统计：
  - 已通过数。
  - 待审数，使用珊瑚色强调。
- 页面顶部提供“待审留言 N”入口，直达 `/admin/comments.html?status=pending`；N 为 0 时不显示。
- 赞/踩保留，文案简化为 `赞 0 · 踩 0`。

### 6.6 P1：反馈与可访问性

- 归档确认改成纸面弹层，不使用浏览器 `confirm()`。
- 成功提示区分动作和数量，不再统一“已完成”。
- 表格有 caption、`scope="col"`、复选框 `aria-label`。
- 菜单按钮 `aria-haspopup="menu"`、`aria-expanded`；支持方向键、Escape、焦点返回。
- 批量浮条 `aria-live="polite"`。
- 触控目标不小于 44px。
- 动画尊重 `prefers-reduced-motion`。

### 6.7 P2：以后再做

- 保存的筛选视图。
- 复制文章。
- 定时发布。
- 标题内联编辑。
- 超过 1000 篇后的全文索引。
- 文章数量趋势或阅读统计。当前没有浏览量数据，不造假指标。

## 7. 关键交互

### 7.1 筛选

- 状态轨是链接，不是表单按钮；切换状态立即带查询参数跳转。
- 搜索、标签、排序放在一个 GET 表单；提交后整页刷新，保留浏览器历史。
- 标签和排序使用现有 `admin-select.js` 自绘下拉，保留原生 `select` 作为数据源。
- 清空只在存在任一筛选时出现。

### 7.2 选择与批量

- 表头复选框控制当前页全部行。
- 卡片视图在工具栏放“全选当前页”。
- 选中行加浅黄油底色/左侧荧光笔线，不使用强烈高亮。
- 批量浮条固定底部；桌面最大宽度 760px 居中，手机左右 12px 通栏，底部留安全区。
- 批量提交后清空选择。

### 7.3 归档与恢复

- 归档确认文案：“把《标题》收进归档？”或“把 N 篇文章收进归档？”
- 说明：“归档后公开页和 API 不再显示。文章数据保留，可随时恢复为草稿。”
- 恢复文案：“恢复后进入草稿状态，不会自动重新发布。”
- 归档成功后状态计数立即变化；当前筛选是“已发布”时，归档文章从列表消失。

### 7.4 行菜单

- 触发按钮显示 `⋯`，带上下文 `aria-label`。
- 菜单项顺序：预览草稿、查看公开页、版本历史、归档/恢复。
- 危险项放最后，使用珊瑚色；普通项用墨色。
- 菜单在视口边缘自动向上/向左翻转，不被表格容器裁切。
- 点击外部、滚动、Escape 关闭。

### 7.5 空状态

- 全站没有文章：“文章架还是空的” + “写第一篇，发布后会出现在公开列表和 API。” + 写新文章按钮。
- 有文章但筛选无结果：“没有符合条件的文章” + “换个关键词，或清空筛选看看全部。” + 清空筛选按钮。
- 归档筛选为空：“归档抽屉还是空的” + “暂时没有收进抽屉的文章。”

### 7.6 加载与失败

- 筛选走原生 GET，不需要遮罩。
- 批量/归档仍使用现有异步表单；成功后替换 `#admin-main`，保留滚动位置和筛选 URL。
- 会话失效沿用 `cream.js` 回登录页提示。
- 数据库失败显示“文章列表暂时不可用，请稍后重试”，不暴露 SQL。

## 8. 视觉规范

### 8.1 方向

“编辑台台账”：

- 状态轨像索引标签，当前状态用墨色实心。
- 表格像摊开的横线账页，行分隔用虚线，不用密集竖线。
- 标签像小纸片，不使用高饱和色块。
- 批量浮条像压在纸面上的黑色工具条。
- 行菜单像从台账里抽出的便签，带纸边和轻阴影。
- 保留米色、墨色、奶油黄、薄荷、珊瑚；不新增紫色或蓝紫主色。

### 8.2 尺寸

- 内容最大宽度：1120px。
- 状态轨高度：38–42px。
- 工具栏控件高度：40px；移动端 44px。
- 表格表头：38px；数据行：64–72px。
- 卡片内边距：14px；卡片间距：10px。
- 批量浮条高度：56px，手机含安全区。
- 菜单宽度：184px；菜单项高度：40px。

### 8.3 字体与数字

- 沿用现有正文和标题字体。
- 数字、slug、时间使用 `ui-monospace`，启用 `font-variant-numeric: tabular-nums`。
- 状态计数 15–16px，重字重；单位“篇”小一号。
- 行标题 14–15px，两行以内；手机 15px。

### 8.4 断点

| 宽度 | 布局 |
| --- | --- |
| ≥ 1024px | 完整七列表格 |
| 761–1023px | 紧凑表格：隐藏标签列和回声列，保留标题、状态、更新、操作 |
| ≤ 760px | 卡片列表；状态轨横向滚动；工具栏纵向堆叠 |
| ≤ 460px | 写新文章按钮通栏；批量浮条通栏；菜单项 44px |

- 任何断点都不允许整页横向滚动。
- 表格自身的横向滚动只在 761–1023px 的极端窄列情况下作为兜底，不承担主要布局。

### 8.5 组件命名

新样式统一前缀 `post-admin-`，避免和留言、媒体、编辑器样式互相覆盖：

## 9. 技术方案

### 9.1 数据层

`PostAdminRepository` 增加：

- `summary(): array{total:int,published:int,draft:int,archived:int,with_changes:int}`
- `paginate(array $filters, int $limit, int $offset): array`
- `countFiltered(array $filters): int`
- `archiveMany(array $ids): int`
- `restoreMany(array $ids): int`

`paginate` 查询：

- 主表 `posts`。
- `LEFT JOIN post_drafts` 取 `draft_updated_at`，避免逐行查工作稿。
- 标签筛选用 `EXISTS`，避免 JOIN 放大结果。
- 搜索使用转义后的 `LIKE`，匹配 `title` 和 `slug`。
- 排序使用白名单映射，不拼接用户输入。
- `LIMIT/OFFSET` 使用整数化后的字面量。

批量补充查询：

- `TagRepository::namesForPosts(array $ids)`。
- `CommentRepository::countsForPosts(array $ids)`。
- reactions 沿用现有 `summariesForPosts`。
- 待审留言总数使用现有 `CommentRepository::count('pending')`。

### 9.2 控制器

`PostAdminController::index()`：

- 解析并校验 `status/q/tag/sort/page/changes`。
- 读取 summary、当前页、筛选总数、标签列表、待审留言数。
- 组装当前查询串，供状态轨、分页和行操作回跳使用。
- 传递 `notice` / `noticeCount`，由模板只输出白名单文案。

新增动作：

- `POST /admin/posts/{id}/restore.html` → 恢复为草稿。
- `POST /admin/posts/bulk.html` → 批量归档/恢复。
- 新路由必须放在 `/admin/posts/{id}` 之前，避免 `bulk` 被当作 id。

写操作统一：

- CSRF 校验。
- 只接受正整数 id。
- 批量最多 100 个 id。
- 归档/恢复都在事务里完成。
- 成功后按提交的筛选参数回到列表。
- 审计事件：`post.archived`、`post.restored`、`post.bulk_archived`、`post.bulk_restored`。

### 9.3 模板

拆成：

- `admin/posts.php`：页面外壳、状态轨、工具栏、分页。
- `admin/partials/posts-table.php`：桌面表格。
- `admin/partials/posts-cards.php`：手机卡片。
- `admin/partials/post-row-actions.php`：编辑按钮和更多菜单模板。

两份布局共享同一个 `$posts` 数组，不重复业务判断。桌面表单和手机表单各自独立，隐藏布局的复选框不参与提交。

### 9.4 样式与脚本

- 新增 `public/assets/admin-posts.css` 与 `.gz`，只在文章页通过 `page_styles` 加载。
- 新增 `public/assets/admin-posts.js` 与 `.gz`，只在文章页通过 `page_scripts` 加载。
- 复用 `admin-select.js` 做标签/排序下拉。
- 复用 `cream.js` 的表单异步提交、加载遮罩和会话失效处理。
- 需给 `cream.js` 增加替换内容后的 `AdminSelect.enhance(current)` 调用，否则异步归档后新页面的下拉会退化成原生样式。
- 新脚本职责：
  - 全选/反选、批量数量、批量浮条。
  - 行菜单定位、键盘和关闭。
  - 纸面确认弹层；没有脚本时保留表单原始提交路径。
  - 不引入第三方库。

### 9.5 不改的东西

- 不改 `posts` 表结构。
- 不改公开页、API、Feed、搜索。
- 不改编辑器发布门禁、版本快照、自动保存。
- 不把归档变成物理删除。
- 不在列表里做批量发布，避免绕过内容健康检查。

- 恢复只回草稿，不自动发布。
