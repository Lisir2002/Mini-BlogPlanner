# 后台文章编辑器重设计蓝图

> 版本：v0.1.40 设计稿  
> 范围：后台文章编辑页、正文格式模型、编辑器交互与视觉  
> 目标：同时兼容 Markdown 与 HTML，保留手账主题气质，先设计评审再落地

## 1. 结论先行

首版建议采用「双源编辑器」而不是直接替换成重型富文本：

- **Markdown 源文模式**：适合日常写作、代码片段、可迁移内容。
- **HTML 源码模式**：适合已有文章、需要精细控制标签的内容。
- **实时预览**：由服务端用同一套 Markdown 解析与 HTML 清洗规则生成，保证“预览所见 = 发布所得”。
- **写作态富文本**作为第二阶段：在双源模式稳定后，再引入 ProseMirror/Tiptap 的块编辑与输入规则。

理由：当前项目是原生 PHP 微内核，没有前端构建链；直接上完整富文本会同时引入编辑器运行时、Markdown 双向转换、粘贴清洗、历史记录与构建发布五项风险。双源模式可以先解决格式兼容和数据安全，再用同一套 `body + body_source` 模型平滑升级。

## 2. 现状审计

### 2.1 已有能力

- 编辑页由 `themes/cream/templates/admin/editor.php` 输出，正文是一个纯 `<textarea name="body">`。
- 保存时由 `plugins/admin/src/PostAdminController.php` 校验，`HtmlSanitizer` 只保留白名单 HTML。
- 正文以 HTML 存在 `posts.body`，文章页直接 `<?= $post->body ?>` 输出。
- 后台表单通过 `cream.js` 的 AJAX 提交，成功后局部替换 `#admin-main`。
- 主题已有完整手账色板：奶油纸、墨色、珊瑚、黄油、薄荷、天蓝，以及纸纹、胶带、印章、手绘阴影。

### 2.2 主要问题

1. **格式单一**：只能粘贴或手写 HTML，Markdown 不会转换，换行与空行经常被浏览器折叠。
2. **没有预览**：保存前看不到真实排版，代码块、引用、图片宽度只能猜。
3. **没有输入辅助**：标题、粗体、链接、代码块、分割线全靠手打标签。
4. **没有保存状态**：是否保存成功、是否有未保存修改，页面没有持续反馈。
5. **没有离开保护**：误点导航会丢失长文。
6. **元数据拥挤**：标题、slug、摘要、标签、状态、正文堆在同一张表单里，写作注意力被切碎。
7. **移动端不成立**：窄屏下侧栏挤压正文，长文编辑和保存都很吃力。
8. **格式切换无契约**：未来若加入 Markdown，必须先定义“原文存哪里、HTML 存哪里、切换是否丢格式”。
9. **HTML 粘贴风险**：当前清洗器覆盖基础标签，但缺少表格、上下标等编辑常见结构；直接放开会让发布页出现不可控样式。
10. **无障碍缺口**：工具栏、错误提示、保存状态都没有键盘路径与状态播报。

## 3. 外部设计研究

| 产品/技术 | 值得借鉴的设计 | 不直接照搬的部分 |
|---|---|---|
| Ghost | 编辑器几乎退到背景，写作面优先；卡片/斜杠插入；发布设置在侧栏 | 卡片体系较重，当前博客不需要完整卡片模型 |
| Notion | 块级结构、斜杠命令、拖拽手柄、块悬浮操作 | 块数据库和多人协作超出当前范围 |
| Bear | 专注模式、字体与排版控制、标签输入自然 | 纯 Markdown 方言与导出策略需另定 |
| Obsidian / Typora | 源码与实时预览的连续感；Markdown 是可信源 | 插件生态复杂，不适合直接嵌入 |
| Tiptap / ProseMirror | Schema 驱动、输入规则、选区工具条、扩展化 | 需要前端构建与序列化策略 |
| CodeMirror 6 | 模块化、轻量、Markdown/HTML 语法高亮、搜索与撤销成熟 | 只解决“源码编辑”，不解决块级富文本 |
| CommonMark | 明确 Markdown 语义，避免各家方言漂移 | 原始 HTML 仍需独立清洗，解析器不是安全边界 |
| W3C ATAG | 创作工具应可键盘操作、可恢复、可访问 | 需要逐项落到组件，而不是只写声明 |

### 3.1 提炼出的六条原则

1. **写作面优先**：正文永远是视觉中心，元数据退到右侧或折叠区。
2. **格式可见**：当前是 Markdown 还是 HTML，必须在页头持续显示，不能靠记忆。
3. **预览即发布**：预览必须复用服务端解析与清洗，不能在前端另写一套规则。
4. **切换有代价提示**：任何可能丢失源格式的转换，都要先说明再执行。
5. **状态常驻**：保存中、已保存、未保存、保存失败，四种状态始终可见。
6. **键盘完整**：所有高频动作都有快捷键，所有按钮都有可见焦点。

## 4. 产品与数据模型

### 4.1 三种编辑模式

| 模式 | 面向场景 | 编辑对象 | 首版 |
|---|---|---|---|
| 写作 | 日常长文、图文混排、块级操作 | 规范化 HTML | 第二阶段 |
| Markdown | 技术笔记、可迁移文本、代码块 | Markdown 原文 | 首版 |
| HTML | 既有文章、精细标签控制 | 规范化 HTML | 首版 |

首版先把 Markdown / HTML 双源做稳；写作态在第二阶段接入同一套保存契约。

### 4.2 存储策略

新增两个字段，公开渲染路径不变：

- `posts.body`：继续保存**已清洗的规范 HTML**，文章页、搜索、摘要、阅读时长都继续使用它。
- `posts.body_format`：`html` 或 `markdown`，记录最后一次保存的编辑模式。
- `posts.body_source`：Markdown 原文；HTML 模式为 `NULL`。

保存规则：

1. Markdown 模式：保存原文到 `body_source`；服务端解析 Markdown，清洗后写入 `body`；`body_format=markdown`。
2. HTML 模式：清洗输入后写入 `body`；`body_source=NULL`；`body_format=html`。
3. 读取编辑页：`body_format=markdown` 时载入 `body_source`；否则载入 `body`。
4. 公开读取：永远只读 `body`，不解析 Markdown，不增加首屏开销。
5. 切换格式：从 Markdown 切到 HTML 并保存前，提示“Markdown 原文将不再保留”；从 HTML 切到 Markdown 时，按 HTML 当前内容生成初始 Markdown，并提示可能丢失复杂标签。

### 4.3 迁移

- `2026112103_add_editor_body_format`：增加 `body_format` 与 `body_source`，默认 `html`。
- 历史文章自动保持 HTML 模式，无需回填正文。
- 迁移可逆：删除两个新列，且不触碰 `body`。

### 4.4 安全边界

- Markdown 解析后必须再次经过 `HtmlSanitizer`；解析器不作为安全边界。
- 保留现有协议白名单：`http`、`https`、`mailto`、站内相对路径、锚点。
- 补齐编辑常见标签：`table`、`thead`、`tbody`、`tr`、`th`、`td`、`caption`、`sup`、`sub`。
- 禁止 `script`、`style`、`iframe`、表单控件、SVG、事件属性与 `javascript:`。
- 预览接口与保存接口共用同一服务端清洗函数，禁止前端预览绕过。
- 保存时比较 `expected_updated_at`，发现其他窗口已修改则提示冲突，不静默覆盖。

## 5. 信息架构与布局

### 5.1 桌面布局

```
┌──────────────── 全局后台顶栏（唯一顶栏） ────────────────┐
│ 文章 / 编辑   已保存 12:04      [预览] [保存并发布]      │
├──────────┬──────────────────────────────┬───────────────┤
│ 手稿目录  │  标题                         │ 发布检查       │
│ 01 标题   │  摘要                         │ 状态           │
│ 02 正文   │  标签                         │ slug           │
│ 03 标签   │  ┌ 编辑区 / 预览区 ─────────┐ │ 摘要           │
│ 04 发布   │  │ Markdown 源文             │ │ 标签           │
│          │  │ 实时预览                  │ │ 封面/日期      │
│          │  └──────────────────────────┘ │ 字数/阅读      │
└──────────┴──────────────────────────┴───────────────┘
```

- 不新增第二条全宽固定顶栏；编辑动作放在页面标题行内。
- 左栏可折叠，宽度 208px；右栏 288px；正文纸面最大 760px。
- 1180px 以下隐藏左栏；980px 以下右栏变为“发布”抽屉。

### 5.2 手机布局

- 单列：标题 → 模式切换 → 编辑区 → 标签 → 发布抽屉。
- 底部浮动操作条：目录、预览、保存；不遮挡输入光标。
- 源码模式默认关闭行号，横向滚动只出现在代码块内部。
- 预览与编辑用分段切换，不做左右分栏。

### 5.3 编辑页层级

1. 页面标题行：返回文章列表、当前文档状态、模式切换、预览、保存。
2. 文档头部：无边框大标题、slug 小字、标签 chips、摘要折叠。
3. 编辑纸面：工具栏 + 编辑区 + 状态栏。
4. 右栏：发布状态、slug、标签、摘要、日期。
5. 辅助层：斜杠命令、选区工具条、离开确认、冲突提示。

## 6. 视觉语言

### 6.1 基调

「编辑部手稿台」：奶油纸面、墨色正文、珊瑚色主操作、黄油色高亮。不是通用 SaaS 白板，也不是暗色代码编辑器。

### 6.2 颜色

复用主题变量，不新增品牌色：

- 纸面：`--paper` / `--cream-1`
- 正文：`--ink` / `--ink-soft`
- 主操作：`--coral`
- 选区与当前行：`--butter` 低透明度
- 辅助信息：`--muted`
- 边框：`--line` / `--line-strong`
- 代码块：深墨底 + 奶油字，沿用文章页

### 6.3 字体

- 标题：系统宋体栈，`"Songti SC", "Noto Serif CJK SC", serif`，40px/1.25，字距 `-0.03em`。
- 正文编辑：系统无衬线，17px/1.95，最大行宽 38em。
- 源码：`ui-monospace, SFMono-Regular, Menlo, Consolas, monospace`，14px/1.75。
- 辅助标签：12px，字距 0.12em，大写英文用 `EDITOR / PUBLISH`。

### 6.4 形状与质感

- 纸面圆角 18px，1px 墨线，双层纸影，不用玻璃拟态。
- 工具栏像一条窄胶带，贴在纸面上沿，不悬浮遮字。
- 右栏像索引卡：顶部 3px 黄油色横条，字段用细线分隔。
- 状态章用珊瑚色小圆点 + 文字，不使用大面积色块。
- 动效克制：150–220ms，`prefers-reduced-motion` 下全部关闭位移。

### 6.5 源码语法色

- 标题：珊瑚
- 强调：墨色加粗
- 链接：天蓝
- 代码：薄荷
- 引用：黄油左边线
- 注释/标记符：`--muted`，弱化但不隐形

## 7. 交互规范

### 7.1 工具栏

- 常驻按钮：撤销、重做、标题、粗体、斜体、链接、引用、代码、图片、分割线、插入。
- 选区工具条：选中文本后出现在选区上方；按钮只保留最常用的 6 个。
- 工具栏按钮必须有 `aria-label`、`aria-pressed` 与键盘焦点。
- 源码模式下按钮插入语法片段；写作态下按钮执行编辑器命令。

### 7.2 斜杠命令

输入 `/` 打开纸片式命令面板：

- 基础块：正文、标题 2、标题 3、引用、无序列表、有序列表、代码块、分割线、图片、表格。
- 搜索：输入关键词过滤。
- 键盘：↑↓ 选择，Enter 插入，Esc 关闭。
- 鼠标：点击插入；面板不抢输入焦点超过一帧。

### 7.3 模式切换

- 页头分段控件：`写作` / `Markdown` / `HTML`。
- 当前模式用珊瑚下划线 + 墨色文字，未选模式用 muted。
- 切换前若有未保存修改，先保存草稿或提示。
- Markdown → HTML：确认“原文将不再保留”；HTML → Markdown：提示“复杂标签可能被简化”。

### 7.4 预览

- 桌面：编辑/预览 58/42 分栏，可拖拽分隔；也可全屏预览。
- 手机：顶部 `编辑 / 预览` 分段切换。
- 预览由 `POST /admin/posts/preview-body.html` 返回清洗后的 HTML，800ms 防抖。
- 预览失败显示行内提示，不覆盖已有预览。
- 预览区使用与文章页相同的 `post-body` 样式，保证排版一致。

### 7.5 保存

- `Ctrl/Cmd + S` 手动保存。
- 停止输入 2.5 秒后自动保存草稿；发布状态不自动改变。
- 状态文案：`未保存` / `保存中…` / `已保存 12:04` / `保存失败，点此重试`。
- 失败时保留本地草稿到 `localStorage`，刷新后提示恢复。
- 离开页面前若有未保存内容，使用原生 `beforeunload` 或站内确认层。

### 7.6 专注模式

- `Ctrl/Cmd + Shift + F` 切换。
- 隐藏左右栏、标签与摘要，仅保留标题、正文、保存状态。
- `Esc` 退出；退出后焦点回到正文。

### 7.7 快捷键

| 动作 | 快捷键 |
|---|---|
| 保存 | `Ctrl/Cmd + S` |
| 预览 | `Ctrl/Cmd + Shift + P` |
| 专注 | `Ctrl/Cmd + Shift + F` |
| 粗体/斜体 | `Ctrl/Cmd + B` / `I` |
| 插入链接 | `Ctrl/Cmd + K` |
| 打开插入面板 | `/` |
| 退出面板/专注 | `Esc` |

### 7.8 状态与错误

- 空标题：标题下方提示，不阻止继续写正文。
- slug 重复：字段级错误 + 建议 slug。
- 预览解析失败：显示错误行号与原因。
- 保存冲突：横幅提示“另一个窗口已更新这篇文章”，提供“载入最新 / 覆盖保存”。
- 网络失败：底部状态条变为珊瑚色，保留输入。

## 8. 无障碍与移动端

- 所有图标按钮有文字替代；工具栏可 Tab 到达。
- 错误摘要使用 `role=alert`；保存状态使用 `aria-live=polite`。
- 颜色对比至少 WCAG AA；源码语法色不能只靠颜色区分。
- 触控目标不小于 44×44px。
- 输入法组合期间不触发斜杠命令与快捷键。
- 横屏手机保留工具栏，隐藏侧栏。

## 9. 实施计划

### 阶段一：双源编辑器（本次落地范围）

1. 数据迁移：`body_format`、`body_source`。
2. 引入 `league/commonmark` 运行时依赖，配置 GFM 子集；渲染后接 `HtmlSanitizer`。
3. 后台读取/保存支持两种格式；补冲突检测。
4. 新增预览接口，复用服务端解析与清洗。
5. 前端引入 CodeMirror 6，构建 `editor.js`；Markdown/HTML 语法高亮、搜索、撤销、自动换行。
6. 重做编辑页布局：页头动作、纸面编辑区、右栏发布检查、手机底部操作条。
7. 自动保存、离开保护、专注模式、字数与阅读时长。
8. 测试：格式往返、HTML 清洗、预览一致性、键盘与移动端。

### 阶段二：写作态富文本

1. 引入 Tiptap/ProseMirror，接入同一保存契约。
2. 输入规则：`#` 标题、`**` 粗体、`>` 引用、``` 代码块。
3. 选区工具条、斜杠命令、块拖拽。
4. Markdown 与富文本转换的丢失提示与恢复。

### 阶段三：协作与历史

1. 版本历史与差异对比。
2. 草稿多端同步。
3. 编辑冲突合并。
4. 发布前检查清单。
